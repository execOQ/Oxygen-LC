Run the automated regressions with:

```powershell
dotnet run --project Tests/ConfigSync/ConfigSync.Tests.csproj
dotnet run --project Tests/BepInExConfig/BepInExConfig.Tests.csproj
dotnet run --project Tests/ChargerLifecycle/ChargerLifecycle.Tests.csproj
```

The sync suite executes the production snapshot codec, typed override wrapper, moon parser, and sync transport using minimal engine/config doubles. It covers large Unicode lists, chunk boundaries, partial/malformed data, protocol/schema/type mismatches, host authority, initial and late joins, live edits, local preferences, disconnects, reconnects, switching to hosting, handler cleanup, and missing-host diagnostics. The BepInEx suite also verifies serialization, config-file persistence, and rollback events against the real BepInEx DLL. Unity, actual network startup hooks, and LethalLib shop mutations still require game verification.

The charger suite executes the production furniture helper, OxyCharger spawn/despawn callbacks, and weather reserve logic with game/Unity/Netcode doubles. Native spawning is modeled as loading placement from disk, separately from current in-memory moves. It covers unconditional registration, matching placeable/parent/terminal IDs, saved placement, waiting for save loading, storage surviving config refreshes and toggles, server-only spawning/despawning, duplicate prevention, late joins, reconnecting with a new unlockable list, and furniture resets. The sync suite also tests weather refreshes without a charger, server-only reserve initialization, late joins preserving consumed reserves, live limit/capacity edits, and automatic refill without a physical charger.

Storage regressions cover unsaved position and zero Euler rotation being applied before network spawn despite stale disk placement; disabled host returns preserving storage without a success broadcast; clients deferring return authority to the host; and real charger callbacks preserving partially consumed and empty reserves through repeated storage/return and config toggles. New rounds, capacity edits while stored, client callbacks, and session resets verify reserve carryover has the correct lifetime. Despawn callbacks run with IsSpawned already false, ensuring reserve capture reads the network variable directly.

Concurrent refill checks execute the production RefillSync service and OxyCharger allocator through queued named messages between independently simulated peers. Clients retain stale reserve replicas and cannot refill until a matching host grant arrives. Tests cover simultaneous manual/automatic refills, host/client competition, insufficient reserves, retries and duplicate replies, failed reply sends, host-controlled increments and weather settings, manual interaction during a pending auto refill, storage before/after allocation, stale charger IDs, disconnects, grants from another host/session, forged senders, invalid amounts, and dead recipients. The config suite also verifies refill session startup/cleanup/reconnection wiring. These do not replace a real Unity/Netcode multiplayer run.

Automatic refill frames are accumulated into bounded batches while awaiting a reply, preserving progress under latency without per-frame messages or speculative local refills. Tests exercise simultaneous batches against a nearly empty reserve and reject invalid batch sizes.

Manual retry regressions run only the session timer with automatic refill disabled: failed request/reply sends recover without additional interaction, reuse the original payload, allocate once, continue through charger storage, and stop on completion or disconnect. Player-state regressions queue requests before server-side death and verify zero grants, unchanged reserve, acknowledged rejection, cached rejection after revival, and successful fresh requests. Server player slots deliberately differ from transport client IDs; missing, invalid, null, and stale mappings are rejected without blocking later valid requests. Player lookup follows Lethal Company's ClientPlayerList scene-player mapping rather than NGO PlayerObject.

Specific lifecycle regressions include a late join with duplicate moons in the client's local file, exception-safe cleanup, an interrupted host-A snapshot followed by host B with different settings using the same client NetworkManager, validation before scalar/dictionary commits, rollback and continued retries after world-effect exceptions, recovery after a corrected host snapshot, disconnect with a reason after exhausted initial sync, and successful reconnection afterward. Request-send exceptions are also retried and terminate through the same failure path.

Host-edit regressions cover NaN/infinity, invalid enums, duplicate/non-finite moon values, oversized snapshots, world-effect failures, restoring rejected edits in the host's local config, subsequent valid edits, and late joins receiving only accepted values. Slow-transfer tests advance a fake real-time clock while delivering chunks beyond ten seconds and verify there are no duplicate requests; a stalled transfer still times out. The production VanillaCanisters helper is tested against active-only GameObject.Find, inactive-child Transform.Find, repeated hide/restore, cache resets, destroyed scene references, and a missing scene.

Multiplayer verification (requires two game instances with this build):

1. Run Oxygen without CSync installed (unless another mod requires it). Set conflicting gameplay values on host/client, including all five moon lists longer than 512 bytes with overrides near the end. Use different HUD, notification, sound, volume, and die-early UI delay preferences.
2. Join and verify host values govern drain, sprint/water/fear modifiers, damage/timing, refill rules, compatibility rules, weather limits, OxyBoost amount/price, charger availability, and the die-early enable switch. Local preferences must remain different. Verify the complete-host-config log message.
3. Edit host gameplay settings during a round, including enabling/disabling OxyBoost and OxyCharger and changing prices. Verify both peers update; enable/disable again to verify restoration. Client gameplay edits must save locally without changing active host values.
4. Join late, disconnect, join another host with different settings, then host locally. Verify overrides and hidden shop entries do not persist. Compare client config files before and after syncing: received host settings must never be written to disk.
5. Repeat with empty moon lists and Unicode names. Visit moons near the end of long lists. Verify the charger returns to its vanilla canisters when disabled and is recreated when enabled.
6. Put a duplicate moon in the client's local config and join a host with valid settings; the join must still sync. A host without compatible sync support must lead to a disconnect reason after ten seconds without progress. The client must be able to join a valid host afterward.
7. During hosting, try invalid moon lists and NaN scalar values. Verify the rejected edits revert on the host and that subsequent valid price/drain edits reach existing clients and late joins. Simulate a slow progressing transfer and verify it can complete after ten seconds, while a stalled transfer eventually disconnects.
8. Move the charger in build mode, store it, and return it with the `oxycharger` command. Repeat from both peers. Store it again, edit unrelated host settings, and toggle charger availability; it must remain stored. Save/rehost and verify moved placement and storage persist. Join late and then reconnect to a different host; verify furniture IDs and placement match that host. Verify a full furniture reset returns the charger to its default position.
9. Move the charger without saving, then disable/re-enable it and store/return it; verify both peers keep the unsaved position and rotation. While stored and disabled, attempt to return it from both host and client; it must remain stored after re-enabling. On an Eclipsed moon, consume part or all of the reserve, then repeat storage/return and config toggles; the reserve must not replenish. A new round or capacity edit should still initialize the intended new reserve.
10. With an Eclipsed reserve near empty, refill simultaneously from multiple clients and the host, both manually and automatically. Verify total granted oxygen never exceeds the reserve and clients wait for host approval. Repeat with latency while storing/returning the charger, and disconnect/reconnect before a reply arrives; grants must not be duplicated or applied in the next lobby.
11. Disable automatic refill, simulate a request/reply send failure, and manually refill once. Recovery must happen without another interaction, including if the charger is stored before the retry. Queue a manual or automatic request, then kill its sender before host processing; the host must acknowledge zero oxygen and leave the reserve unchanged. After revival, a fresh request must still work.

All peers need this sync implementation. Older Oxygen builds cannot exchange settings with it.
